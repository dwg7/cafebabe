# 分析レポートの検査ハーネス — 数・主張・人の判断を機械で縛り、残る誤りは独立レビューで拾う

データ分析のレポート(本文に数と主張が並ぶ文書)を、書いた本人の注意力に頼らず、機械的な検査と
独立した目で縛る方法について。`patterns/verification-discipline-self-checks.md`(自分の検査手順を疑う)
の、レポート執筆への適用にあたる。
2026-10-22、`dwg7/do-survey`からの寄稿(DECISIONS.md D34・D35・D36・D39・D41・D48)より。実例は
1プロジェクトの積み上げで、他プロジェクトでの再現は未確認。

## レポート本文の数字は、同じフォルダの根拠表か式で裏付けられるかを機械的に検査する

**タグ**: 個別事情(do-survey。実例が1プロジェクトのため一般則への格上げは見送る)

**状況(Context)**
分析レポート(Markdown)の本文に、件数・割合・相関などの数が多数並び、同じフォルダに
スクリプトが生成した「根拠表」がある場面。

**問題/対立する力(Problem / Forces)**
本文を書く過程で、会話の中で計算した数、足し算・平均の結果、別のレポートからの写しが混ざる。
手で突き合わせるのは続かず、**検査を入れる前の本文は、根拠表にない数が多かった**。

**解決(Solution)**
`scripts/check_numbers.py`が、本文の**2桁以上の数と小数**を拾い、(a)同じフォルダの生成済み根拠表に
あるか、(b)そのフォルダの`checks.csv`に書いた**式(`expr`)か参照(`ref`)**で裏付けられるかを確かめる。
式で使う数もまた根拠表にあることを要求する。入れる前は、本文の数368のうち45が根拠表になかった。
会話の中で出した内訳を根拠表に足して17に減らし、足し算・平均・他レポートの数を`checks.csv`に
書いて0にした。**わざと変えた数を検査が拾うことも確かめた**(検査自体の検定。
`patterns/verification-discipline-self-checks.md`の「検査を書いたら、わざと失敗させて…」と同じ)。

限界と、運用で見つかった落とし穴:
- **どの項目の数かまでは見ない**(同じ値の別の項目に差し替えても通る)。
- 小数も数えないと、相関の古い値が素通りした(D35)。
- `ref`は、CSVの「数,日付」の並びを1つの数と読む(カンマを桁区切りとして外すため)。人口を根拠表の
  列に出して裏付ける形にした(D48)。
- 検査の範囲外の本文に誤りが集まる(下の独立レビュー参照)。範囲を広げる(column・longtermの本文へ、
  D41)。URLと西暦の年は数えない。

**実例(Known uses)**
- `dwg7/do-survey` — D34(2026-10-13)で導入、D35・D41・D48で拡張。

## 会話で計算した数は、根拠表に移すまで根拠ではない

**タグ**: 個別事情(do-survey)

**状況(Context)**
講演の資料などのために、エージェントとの会話の中で数を計算して伝え、後でそれを根拠表と
本文に移す場面。

**問題/対立する力(Problem / Forces)**
会話の中の暗算や即席の集計は、生成スクリプトを通さないので、**移したとき値が変わる**ことがある。

**解決(Solution)**
会話で出した数は、生成スクリプトで根拠表にしてから使う。変わった値は、何が違ったかを記録する。

**実例(Known uses)**
- `dwg7/do-survey` — D48(2026-10-21)。「計画と用地で87%」と伝えていたが、不明を除く割合86.5%の
  丸めで86%が正しかった。「別海町の道内最多は6」と伝えていたが、同数の年度の扱いで数が変わり、
  単独なら5、同数を含めると6だった。**単独と同数を含む数を両方出す**形にした。

## 発見の台帳 — 1行1発見、確度の状態を持たせ、修正された主張を履歴にする

**タグ**: 個別事情(do-survey)

**状況(Context)**
レポートが複数に増え、後のレポートが前のレポートの主張を直す場面。

**問題/対立する力(Problem / Forces)**
どの主張がどの根拠で、どの確度かが、レポートの本文に散らばる。後で直された主張が、元の
レポートに残って読まれる。

**解決(Solution)**
`reports/findings.csv`に**1行1発見**で書き、`scripts/check_findings.py`が検査と一覧
(`findings.md`)を生成する。状態は次の5つ。
- **確認**: 外部資料(oracle)で確かめた
- **集計**: データの集計だけの主張
- **推定**: 因果の読み(外部資料で確かめていない)
- **否定**: 後で誤りと分かった
- **置き換え**: 後の発見に置き換えた(どの発見に置き換えたかの列を持つ)

「後のレポートで修正された主張」の表は、台帳の否定・置き換えの行に当たる。外部資料で確かめた
ときは確度を上げ、確かめられなかった部分は別の発見(推定)に分ける。

**実例(Known uses)**
- `dwg7/do-survey` — D34で導入(48件)。2026-10-22時点の台帳は、確認4・集計57・推定9・否定8・
  置き換え6。D42は台風10号の復旧を外部資料で確かめ、確認に上げた主張を範囲に絞り、確かめられ
  なかった増加分を推定として別の発見に分けた。

## 台帳の主張を、根拠表とは別の計算で元データから再現する

**タグ**: 個別事情(do-survey)

**状況(Context)**
台帳の数量の主張が、根拠表に基づいているとき、根拠表を作るスクリプト自体が誤っている恐れがある。

**解決(Solution)**
`scripts/verify_findings.py`が、台帳の主張を、**根拠表を作るスクリプトとは別に書いた計算**で元
データから再現する(導入時は25項目)。導入時に全スクリプトを流し直し、出力がコミット済みと
一致することも確かめた(D35)。このとき見つかったもの:
- 計画機関の規則に当たらない案件が47件あった(規約の「0件」と食い違い)。規則を足して0にした。
- 主張がいくつか直った(「30〜45日」→「30〜44日(初夏は23日)」、相関+0.70→+0.68など)。
- 集合の並びを実行ごとに変わる順に任せていた箇所があった。**同点は名前の順にして**、
  `PYTHONHASHSEED`を変えて2回生成し、全レポートの根拠表が一致することを確かめた(D36)。

**実例(Known uses)**
- `dwg7/do-survey` — D35・D36(2026-10-13〜14)。

## 人が書く仕分けの表と、計算で求めた集合は、ちょうど一致しなければ止める

**タグ**: 個別事情(do-survey)

**状況(Context)**
人が判断した仕分け(種類・原因)を表(CSV)に書き、その行の集合が、別の計算(例: 「予想外」の
指標の集合)と対応する場面。

**問題/対立する力(Problem / Forces)**
分類規則を変えると、計算側の集合は変わるが、人が書いた表は古いまま残る。仕分けの漏れや、対象でなく
なった行の混入に気づかない。

**解決(Solution)**
生成スクリプト(`scripts/overview_tables.py`)が計算で集合を求め直し、`events.csv`の行がその集合と
**ちょうど一致しなければ止まる**。仕分けを変えたら、年度ごとの本文も同じコミットで直す。

**実例(Known uses)**
- `dwg7/do-survey` — D39(2026-10-16)。分類規則を変えたとき、予想外の指標が1つ消えたことを、この
  検査が止めて知らせた(D41の規則変更で予想外が49→48になった件がこれに当たると思われるが、どの変更でこの検査が止まったかの記録は確認していない)。

## 機械の検査が全部通っても誤りは残る。作り手と別の文脈の独立レビューで拾う

**タグ**: 個別事情(do-survey)

**状況(Context)**
上の検査がすべて通った状態のレポート群。

**問題/対立する力(Problem / Forces)**
検査は、本文の数が根拠表と合うことは保証するが、**何を根拠表の対象にしたか**は保証しない。
do-surveyの報告では、数の検査が全部通っていても、次のような誤りが残った。
- 比べる起点の年の選び方
- 相関の抜き方
- 別の記録からの写し
- 項目の取り違え

さらに、**誤りは検査の範囲外の本文に集まっていた**。

**解決(Solution)**
`reports/`の全体を、作り手と別の文脈のレビュアー4人(ファクトチェック・論理の一貫性・客観性・
定量性の観点)に独立に読ませた。**レビュアーは読むだけで、指摘は作り手が元データで確かめ直して
から直す**。利用枠の都合で上位のモデルが使えず、作り手と別の文脈のモデルで行った(D41)。結果として
分類規則、仕分け、根拠表、検査の範囲が直った。指摘を元データで確かめ直す手順が、レビュアーの
誤指摘を直接取り込まない歯止めになる(`patterns/verification-discipline-cross-session.md`の
ピアの主張の扱いと同じ型)。

**実例(Known uses)**
- `dwg7/do-survey` — D41(2026-10-21)。台帳の10件を直し、仮説の一般化(推定)と基礎調査との同期
  (集計)を2件足した。検査の範囲もcolumn・longtermの本文に広げた。
